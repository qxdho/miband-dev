# 文件清单（FS List）— 小米手环 10 Pro Lua 表盘

一个**只做一件事**的表盘：按下按钮后，用固件自带的 `ls -R /` 递归列出整台设备的所有目录和文件（不限深度），把结果写入 `/data/fslist.txt`。

- 目标机型：小米手环 10 Pro（p67 容器，资源路径 `_lua/xiaomi-band-10-pro/`）
- 输出文件：`/data/fslist.txt`（UTF-8 文本）
- 扫描范围：`/` 全部，包括 `/proc`、`/dev`
- 依赖：无。不 push 任何文件到设备，不修改系统分区，只读扫描 + 写一个文本文件

## 安全设计

打开表盘**不会执行任何命令**，只有按下「扫描并写入」按钮才会动作。

这是刻意的：如果表盘在加载期执行动作，一旦动作导致系统异常，重启后表盘会再次执行，形成「开机就崩 → 无限重启」。本表盘加载期只创建界面，因此即使扫描中途设备重启，重启后也只会静静显示，不会再次触发。

按钮回调整体包在 `pcall` 里，并有 `busy` 闸门防止连点重入。扫描可以重复执行，每次都会覆盖旧清单。

## 输出格式

文件第一行是生成时间，之后是 NuttX `ls -R` 的原始输出：

```
Tue Oct 26 17:20:00 2026
/:
data/
dev/
proc/
system/
/data:
offlinelog/
fslist.txt
/data/offlinelog:
device.log
...
```

约定：

- 以 `:` 结尾的行是**目录头**（该目录的完整路径）
- 目录内的子目录以 `/` 结尾
- 其余行是文件名
- 没有隐藏文件的概念，除 `.` 和 `..` 外全部列出

NuttX 没有 `find`、`busybox`、`tar`、`grep`，`ls -R` 是固件里唯一可靠的全盘递归入口。

## 安装

把 `dist/fslist.bin` 按你平时安装第三方表盘的方式装到 10 Pro 即可（包 ID `990000000002`，显示名「文件清单」，例如用 AstroBox / Canopus 投递通道）。

装好后打开表盘 → 按「扫描并写入」→ 等待完成提示。

## 取回结果

`/data/fslist.txt` 是普通文件，可用你惯用的方式取回（例如另一个带 shell/文件导出能力的表盘、调试工具或离线日志目录）。表盘本身只负责生成，不负责传输。

## 构建

需要 Node.js（无第三方依赖）：

```sh
./build.sh
```

等价于：

```sh
node tools/p67build.cjs build spec.json dist/fslist.bin
node tools/p67build.cjs verify dist/fslist.bin
```

`tools/p67build.cjs` 是 p67 容器打包器（源文件 `p67build.js`，因本仓库 `package.json` 为 ESM 而改名为 `.cjs`）。它会校验：魔数、版本 `0x10003`、`deviceFlag 0x800`、预览块 336×480、资源块连续且长度自洽。

## 离线冒烟测试

`tools/smoke.lua` 用假的 `lvgl` 和假的 shell 跑一遍 `main.lua`，验证：

1. 加载期零 shell 调用
2. 点击后执行 `ls -R / >> /data/fslist.txt`
3. 成功路径显示目录数/行数/字节数
4. `ls` 返回失败但已有内容时显示「部分完成」
5. `ls` 什么都没写时显示「没有扫到任何目录」
6. 可以再次点击重新扫描

```sh
lua tools/smoke.lua
# PASS: 加载期零执行、成功路径、部分失败路径、空结果、重复扫描均符合预期
```

没有 `lua` 命令时，该测试可跳过；它只用于开发期校验，不影响打包。

## 目录结构

```
fslist/
├── main.lua            # 表盘逻辑（唯一需要改的文件）
├── spec.json           # 10 Pro 容器描述
├── preview.block       # 预览图块（336×480）
├── build.sh            # 构建 + 校验
├── dist/fslist.bin     # 构建产物，装这个
└── tools/
    ├── p67build.cjs    # p67 容器打包/校验器
    └── smoke.lua       # 离线冒烟测试
```

## 说明与限制

- **预览图**：`preview.block` 取自官方 Canopus 模块管理器容器（同为 10 Pro、336×480），仅作为管理器里的缩略图占位，不影响功能。想换成自己的图，需要按同样的预览块格式替换。
- **扫描耗时**：`ls -R /` 是同步执行的，扫描期间界面无响应属正常，设备越大越久。完成后会显示目录数、行数、字节数。
- **错误容忍**：个别目录无权限时 `ls` 可能返回非零退出码，但已写入的内容仍然保留，界面会显示「部分完成」。
- **只适用于 10 Pro**：8 Pro 的资源前缀和容器布局不同，不要混用。
- 如果 `ls` 因为极深的目录或异常节点中断，清单会保留中断前的内容；可重启后重试。

## 已验证 / 未验证

- 已验证（本机）：容器结构通过 `p67build` 校验；Lua 逻辑通过离线冒烟测试；加载期零执行。
- 未验证（无真机）：实际安装、`ls -R /` 在 10 Pro 上的完整耗时与边界目录行为。首次使用建议先在一次扫描后确认 `/data/fslist.txt` 大小与内容正常。
