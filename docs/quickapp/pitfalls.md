# 快应用十大坑

<StatusBadge status="sourced" verified="2026-10-24" />

> 这些坑按「踩到的人有多少」排序。每条都尽量给出判断方法和出处；没有出处的标「待验证」，别当真理。

## 1. 有 Vela ≠ 有快应用引擎

红米手环 3 搭载 Vela，但**没有快应用引擎**，装不了快应用。买设备或给别人推荐前先查[机型矩阵](/start/models)。

**判断方法**：看官方规格页是否写明支持快应用，或直接问有同款的人。不要只看「VelaOS」四个字。

## 2. 分辨率写死

手环 9 是 192×490，手环 10 是 212×520，手环 9 Pro 是 480×336。写死 `px` 的布局换机型必崩。

**做法**：用百分比 / `rpx` 类相对单位，留安全区，先在小屏机型上调。

## 3. 圆角与安全区

圆角从 48px 到 999px（胶囊形）都有。贴边内容会被切掉。

**做法**：把关键信息放在屏幕中央区域；装饰元素才贴边。

## 4. 模拟器能跑，真机白屏

模拟器分辨率、系统版本、权限模型都可能和真机不同。模拟器通过只说明「代码没语法错」。

**做法**：尽早拿真机验证；至少在一台目标机型上跑通再宣布完成。

## 5. manifest 权限没声明

用 `@service.health`、传感器等能力时，`manifest.json` 里不声明就会在真机上静默失败或直接报错。

**做法**：先查官方 API 文档的权限要求，再对照 manifest 逐项勾。

## 6. 包体积超限

`.rpk` 有体积限制，塞大图/大字体很容易超。

**做法**：图片压缩、按需加载、矢量优先；打包后看产物大小。

## 7. 签名/证书问题

打包和安装对签名有要求，证书配置错了表现为「装不上」而不是明确报错。

**做法**：先跑通官方模板的签名流程，再改自己的包名。

## 8. 把 AiotJS 当浏览器

AiotJS 是 quickjs 衍生，类 Vue 语法，但**没有 DOM**，也不保证所有 ES 新特性/浏览器 API 可用。

**做法**：只用文档列出的组件与 API；遇到 `window`、`document`、`fetch` 先假设不可用。

## 9. 生命周期与后台限制

手环资源紧张，应用切后台/息屏后的行为与手机不同。定时器、长任务容易被挂起。

**做法**：不要依赖长时间后台运行；把状态存下来，回到前台再恢复。

## 10. 固件升级后一切重来

手环固件更新可能改 API、改权限、改安装方式。网上教程的「可用」有保质期。

**做法**：记录你验证时的固件版本；本站每页都要求填 `verified` 日期就是为这个。
