# 应用隐藏与免重启模式

<StatusBadge status="sourced" verified="2026-10-25" />

快应用的隐藏与显示需要重启才能生效。根本原因在于，固件在开机时依据 `/data/apps.json` 重建内存注册表：条目被移出该文件后，重启时不会为对应应用创建节点；此后的显示操作找不到节点，只能再次重启。

固件未提供可安全调用的运行时重新注册入口。免重启显示只能保留 `apps.json` 条目，并通过注册表隐藏位与开机补偿维持隐藏状态。两种模式各有代价，默认仍为重启模式。

## 现象

- 隐藏应用后桌面图标立刻消失，`app_launcher_del` 返回成功。
- 重启后将条目写回 `/data/apps.json` 并执行显示操作，图标不会出现，仍需再次重启。
- 开机日志中出现多条 `[launcher] app_launcher_del: app_launcher_del app`，但没有 `add icon`。

## 固件的三层状态维护

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 持久化名单 | `/data/apps.json`、`/data/apps.json_hide` | 开机时决定哪些应用已安装 |
| 内存注册表 | `APP_REGISTRY`（`0x200E_B640`）链表 | 运行时按包名或 app_id 查找应用；节点 `+0x08` 包名、`+0x0C` 图标路径、`+0x10` app_id |
| 桌面图标 | `LAUNCHER_DESKTOP_LIST` 加 LVGL 对象 | 桌面显示的图标；`app_launcher_del/add` 只改这一层 |

常规隐藏做法是将条目从 `apps.json` 移至 `apps.json_hide`。条目一旦不在 `apps.json` 中，下次开机时固件即认为该应用未安装，不会为其创建注册表节点。

## 清除隐藏位对未注册节点无效

`app_launcher_add`（`0x0C51_3A44`）先按 app_id 查找注册表节点，节点不存在时直接返回 0。节点存在时进入记录创建回调 `FUN_0C513700`：

```text
ldrb.w r2, [r0, #0x3c]
lsls   r1, r2, #31        ; bit0 = “应隐藏”
bmi    0x0C5137A4         ; 打 “The app need hidden”，返回 0
```

由此可以得出两条结论：

- 对于仍在注册表中的节点，清除 `+0x3C` 的 bit0 后 `add` 可以成功；
- 对于重启后未注册的应用，`find_node` 返回 0，清除隐藏位的代码不会执行，`add` 无法成功。

第二条是必须再次重启的直接原因。

## 运行时注册入口

固件与公开实现中均不存在可安全调用的通用入口：

| 入口 | 结论 |
| --- | --- |
| `quickapp_register_app`（`0x0C54_9679`） | 可创建节点并调用 `app_launcher_add`，但传入空 `extra` 会在 `strdup(NULL)` 处崩溃，已在真机上触发 busfault；该函数是 interconnect 内部路径，不保证本地快应用可启动 |
| `quickapp_install_locally` | native handler 最终仍经由 `quickapp_register_app`，参数来自 proxyquickapp 内部，Lua 与模块无法直接构造 |
| `launcher_data_init` | 只在开机总初始化时运行一次，没有对外 reload API |
| 社区实现 | Shellpp-II 的应用管理文档同样写明 hide/show 需重启生效，未提供免重启注册 |

因此运行时补注册在现有固件上没有可靠实现。

## 两种模式

Chaos 应用管理页 1 顶部提供「免重启显示」开关，状态保存在 `/data/chaos/appmgr_apply.cfg`。

| 项 | 模式 A：重启生效（默认，开关关闭） | 模式 B：免重启显示（开关开启，保留条目） |
| --- | --- | --- |
| 隐藏 | 条目从 `apps.json` 移入 `apps.json_hide`，同时置节点 `+0x3C` bit0、删除图标 | 不改动 `apps.json`，只将包名记入 `/data/chaos/appmgr_keep.bin`，置 bit0、删除图标 |
| 显示 | 写回 `apps.json`，重启后由固件重新注册；本机仍能找到节点时立即 `add` | 从名单摘除，清 bit0、`add` 图标，立即生效 |
| 生效时机 | 重启后 | 立即 |
| 配置语义 | 与其它工具读写同一份配置一致 | 与 `apps.json` 的实际可见性不一致 |

### 模式 A：重启生效

- 隐藏与显示都以 `apps.json` 与 `apps.json_hide` 之间的移动为准，重启后固件重新注册；
- 本机仍能找到节点时，`add` 可立即执行，但重启后仍以名单为准；
- 与其它工具共用同一份配置，语义一致性最高，因而作为默认模式。

### 模式 B：免重启显示

- 隐藏时保留 `apps.json` 条目，只记录包名并置 bit0、删除图标；
- 显示时从名单中摘除条目、清除 bit0 并 `add` 图标，无需重启即可生效；
- 开机补偿由模块定时器在启动窗口结束后读取名单，逐个置 bit0 并删除图标，避免图标残留在桌面。

模式 B 的代价：

| 代价 | 说明 |
| --- | --- |
| 开机时图标短暂闪现 | 取决于 `rc.d` 与桌面初始化的先后 |
| 其它工具误判 | 读取 `apps.json` 时仍会认为该应用可见且已安装 |
| 首次显示仍需重启 | 切换模式前已在 `apps.json_hide` 中的应用，节点需要等到下次开机才会注册 |
| 切回模式 A 需重启 | Chaos 会将名单条目移入 `apps.json_hide`，随后仍需重启 |

两种模式都只修改应用名单与图标，不删除应用数据。

## 操作步骤

### 模式 A

1. 打开 Chaos 应用管理页 1，确认「免重启显示」开关处于关闭状态。
2. 在列表中选择应用执行隐藏，条目由 `apps.json` 移入 `apps.json_hide`，图标随即消失。
3. 重启设备，固件按新名单重建注册表，应用不再出现。
4. 需要恢复时执行显示，条目写回 `apps.json`，界面提示「重启后显示」。
5. 再次重启，固件重新注册节点并建立图标。

### 模式 B

1. 在页 1 打开「免重启显示」开关，配置写入 `/data/chaos/appmgr_apply.cfg`。
2. 执行隐藏，包名写入 `/data/chaos/appmgr_keep.bin`，图标立即消失。
3. 执行显示，包名从名单摘除，图标立即恢复，无需重启。
4. 隐藏后重启设备时，模块在启动窗口结束后执行补偿，重新置 bit0 并删除图标。

## 排除项

`/data/chaos/appmgr_excl.bin` 记录不参与一键隐藏或显示的应用，格式为 `EX01` 加 40×44 字节包名。被排除的应用不出现在页 1 列表中，可在页 7 中逐项取消排除。排除项只影响一键操作，不影响单点隐藏与显示。
