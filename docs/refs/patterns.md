# 原生开发模式：渲染、UI 与集成

<StatusBadge status="unverified" verified="2026-10-26" />

这页把原生模块开发中反复出现的问题抽象成模式，不针对任何具体项目。按「画面从哪来」分成三条渲染路径，再给生命周期、固件接口、性能与检查清单。

## 一、三条渲染路径

| 路径 | 谁在画 | 模块做什么 | 典型代价 | 适用 |
| --- | --- | --- | --- | --- |
| A. 自绘帧缓冲 | 模块自己（CPU） | 逐像素写 RGB565，按行/条带提交 | 算力最贵，要自己管同步与内存 | 3D、游戏、特殊视觉效果 |
| B. 系统文本控件 | 固件 UI | 只发文本、控件类型、布局与样式 | 控件表达力有限，绑定固件版本 | 聊天、工具、表单、纯文字界面 |
| C. 系统控件树（LVGL） | 固件 LVGL | 建对象树、设属性、接事件 | 生命周期复杂，易 UAF/错位 | 多页设置、列表、图标界面 |

选型顺序建议：

1. 系统控件能表达 → 选 C；
2. 只需要文字与简单布局 → 选 B，成本最低；
3. 画面是系统控件做不到的（体素地形、动画、逐像素效果）→ 才选 A。

## 二、自绘路径（A）

### 缓冲从哪来

一块 480×336 的 RGB565 帧缓冲需要 `480×336×2 = 322,560` 字节。模块自身 `.bss` 往往只有几 KB，装不下，因此缓冲通常由平台提供，模块通过「借用 / 归还」协议使用：

```
borrow()  → 拿到可写缓冲指针（或缓冲槽位）
写若干行
release() → 归还，交给显示侧
```

实现上常见的是两个指针加一个状态机：`+0x560` / `+0x564` 存前后缓冲地址，`+0x568` 存状态（空闲 / 借出 / 已提交）。写错状态会导致撕裂或花屏。

### 行式、条带式渲染

不要一次渲染整帧再提交。更稳的做法是把一帧拆成若干「步」：

```
begin()        准备相机、裁剪、雾与光照参数
step_rows()    渲染一段行，写入缓冲
step_rows()    …
submit()       提交这一段（脏矩形 / 命令列表）
```

好处：单次占用 CPU 时间可控，掉帧表现为画面局部更新，而不是整帧卡死；也方便与垂直同步对齐。

### 不建深度缓冲的列式求交

体素画面可以用「逐列光线投射」代替三角形光栅：

- 每列从相机方向发射一条射线；
- 沿射线做 DDA，找到最近命中的方块面；
- 采样该面纹理，写入这一列像素。

这样每列只保留最近命中，不需要 `z-buffer`，省下一整块与帧缓冲同尺寸的内存。代价是每像素的浮点运算量更大。

### 软浮点的现实

如果目标 ABI 是 soft-float（`.ARM.attributes` 里 `EF_ARM_ABI_FLOAT_SOFT`，导入 `__aeabi_fmul`、`__aeabi_fdiv` 等），每次乘除都要走 libgcc 函数调用，逐像素浮点会非常贵。可用的优化：

- 帧内能预计算的量提前算好（相机矩阵、光照方向、列方向向量）；
- 远距离用整数/定点近似，近距离再上浮点；
- 按列粗判（区块可见性、面朝向、视距），先排除再精算；
- 水面、雾、天空这类大面积区域用低分辨率或查表。

### 提交与同步

把「渲染完成」与「上屏」分开：

- 每次提交一个脏矩形（或一段命令列表），硬件/驱动只搬运变化区域；
- 用 `present_ready` / `frame_released` 之类的回调控制节拍，避免在缓冲仍被显示侧读取时覆写；
- 命令列表通常有长度上限（例如单次 126 条），超了要拆批。

### 边界校验

自绘代码最容易在坐标上越界。至少校验：

```
0 <= x, y, w, h
x + w <= 480
y + h <= 336
offset + w*h*2 <= buffer_size
```

常量可以写成 `0x275FF`（`480*336 - 1`）和 `0x4EBFF`（`480*336*2 - 1`）这种形式做上界判断。

## 三、系统控件树路径（C）

### 对象树结构

典型结构是三层：

```
page
 ├─ title（标题栏）
 └─ content（内容容器）
     ├─ row[0]（label / icon / picker）
     ├─ row[1]
     └─ …
```

页面只负责「建树 / 拆树」，内容变化通过重建子树表达。

### 四条生命周期规则

控件树的问题几乎都出在「对象什么时候能删」。四条规则：

**1. 不在事件回调里删除当前对象**

事件派发时框架正在遍历控件树，回调里删除当前控件会让遍历器持有悬空指针（use-after-free），表现为花屏、重叠或死机。做法是回调里只置一个「待重画」标记，真正的删除交给常驻定时器（不在事件派发上下文中执行）。

```
on_click:
    request_render(page_id)   // 只置标记
    return

on_timer:
    if pending[page_id]:
        rebuild(page_id)      // 此时删除是安全的
```

**2. 重建，而不是就地刷新**

就地刷新旧对象时，`align_to` 读到的仍是上一轮的几何（坐标、尺寸、父容器内边距），对齐会算错。做法是先删除整棵内容子树，再走与首次建页完全相同的 build 路径。

```
rebuild(page):
    if page.built:
        delete(page.content)
        delete(page.title)
    page.content = create_container()
    page.title   = create_title()
    build_rows(page)          // 与首次完全相同的路径
```

代价是性能，收益是几何永远干净。

**3. 槽位必须清满**

页面常用固定容量数组缓存控件句柄。删除对象后如果只清「本次用到的槽位」，其余旧句柄悬空，下次重建复用即访问已释放对象。清理时写满整个数组，容量上限只保留一个常量来源。

**4. 用全局前台页做事件路由**

同一套回调可能被多个页面共用。回调里要先判断「当前前台页是谁」，再操作对应页面的控件：

```
fg_page = 0        // on_resume 时更新
on_row_event(slot):
    page = fg_page
    handle(page, slot)
```

## 四、系统文本控件路径（B）

这条路径的模块代码通常只有「页面 + 文本 + 属性」：

- 控件通过属性编号配置：位置、尺寸、对齐、颜色、可见性、文本内容；
- 布局用百分比而不是像素，内部按 `/100` 换算；
- 页面生命周期由框架回调：`create` / `resume` / `pause` / `destroy`，模块注册一个描述符（函数指针表）即可；
- 中文输入依赖模块自带的拼音音节表与候选逻辑，字模由系统提供；
- 模块里没有字体数据，是判断「渲染交给系统」的强信号。

## 五、与固件对接：硬编码地址的代价

原生模块无法导入固件符号，常见做法是把固件函数地址写死，然后 `blx` 过去：

```
movw r2, #0x2491
movt r2, #0x0458
bx   r2            // 调到固件里的某个 UI 函数
```

特征与风险：

- 符号表里没有 `UND` 符号，也没有对应库的符号名，但 `.text` 里出现 `0x04xxxxxx` 这类绝对地址；
- 地址与固件版本强绑定，换固件就崩；
- 调试困难，崩溃现场往往只剩 PC 指向陌生地址。

缓解办法：

1. 启动时探测固件版本/特征字节，不匹配就拒绝加载并回退；
2. 把地址集中在一张表里，按版本选择，不要散落在业务代码；
3. 关键调用包一层，失败可观测（日志、错误码），不要静默；
4. 灰度发布，先小范围验证再全量。

## 六、性能与内存预算

以 480×336 面板为例：

| 项 | 数值 | 说明 |
| --- | --- | --- |
| 单帧 RGB565 | 322,560 B | 320 KB 量级 |
| 双缓冲 | 645,120 B | 前后缓冲各一块 |
| 深度缓冲（若使用） | 322,560 B 起 | 能省则省 |
| 命令列表上限 | 约 126 条/批 | 超限需拆批 |

经验：

- 避免每帧动态分配，改用静态区或 arena；
- 渲染与提交分离，把长任务切成固定预算的步；
- 先做可见性裁剪，再进逐像素循环；
- 在软浮点平台上，先测量再优化，优先减少函数调用次数。

## 七、开发检查清单

- [ ] 选型与需求匹配（A/B/C 是否选对）
- [ ] 帧缓冲来源、所有权、双缓冲状态机是否闭环
- [ ] 所有坐标与偏移是否做边界校验
- [ ] 渲染与提交是否分离，是否有防撕裂节拍
- [ ] 控件删除是否避开事件回调，是否走定时器
- [ ] 重建路径是否与首次建页一致
- [ ] 槽位数组是否每次清满
- [ ] 事件路由是否判断前台页
- [ ] 固件地址是否集中管理，是否有版本探测与回退
- [ ] 资源路径、权限、掉电保存是否验证
- [ ] 崩溃是否有可观测输出（日志 / 错误码）

## 八、速查

| 问题 | 优先排查 |
| --- | --- |
| 花屏、局部乱码 | 双缓冲状态机、事件回调中删对象、槽位未清满 |
| 错位、重叠、空白 | 就地刷新导致脏几何、布局百分比换算 |
| 卡顿、掉帧 | 整帧一次渲染、软浮点热点、每帧分配 |
| 换固件即崩 | 硬编码地址未探测、结构体偏移变化 |
| 死机无输出 | 内核态越界、空指针、未处理错误码 |
