# 17 · 控制中心磁贴点击：可行性结论与逆向记录

> 写于 2026-10-22。接 `docs/16-逆向交接-控制中心与LVGL地址.md` §5.3「接管已有磁贴点击」。
> 本文的结论是**这条线不划算、建议封存**（§1），但过程中确认的地址视图纠正（§3）对 LVGL 样式线仍有价值，磁贴结构（§5–§6）留给以后有兴趣的人。

## 1. 结论先行

| 问题 | 结论 |
| --- | --- |
| 磁贴点击的代码位置能找到吗 | **能**，已定位到条目级（§5、§6） |
| 用 Chaos 现有能力接管它现实吗 | **不现实**，四条硬约束见下 |
| 有没有省事的替代 | 只有「点了会打开别的 App」的磁贴能蹭 `app_launcher`（方案 D），但它拦不住「在原地切换状态」的磁贴（勿扰/抬腕/亮度/省电） |
| 建议 | **封存**。除非将来有能力在运行期改固件 `.text` / 字面量池，或改用「注册同名应用」的旁路 |

四条硬约束：

1. **Chaos 的能力边界是资源替换，不是代码补丁**。`supervisor/src/res_hook.rs` 的 106 条 `Rule { dir, name, stem }` 只换 `/resource/...` 下的图；页面能力在 `fw_api`（注册自己的 page/row 回调）。全仓没有「写 `.text` 或改字面量池」的设施。而接管点击最早的一步（把回调指针换掉）恰恰就在只读字面量池里。
2. **没有统一分发器**。应用侧共 46 处 `lv_obj_add_event_cb(obj, cb, 7, udata)`，**每个磁贴一个专属回调**，回调地址是各自函数的字面量池常量。没有一个「按 app_id 查表」的总开关可以一钩全盖。
3. **入口函数在文件里断链**。磁贴描述初始化 `file 0x4424C0` 既无 `bl` 调用者，也无任何字面量指向它（`0x0C4424C1` / `0x1C3F5081` / `0x2C5025C1` 全 0 命中）→ 绑定在运行期/RAM 里建立，静态分析到此为止。
4. **写 flash 有事故先例**。真机上改固件代码需要内核模块级写权限；`920e5e3`（清 arc INDICATOR）就已导致真机重启。收益（换一个磁贴的点击）与风险不成比例。

## 3. 地址视图：16 号文档的 A 视图基址漏了 `0xC0000`

16 号文档写「A 基址 `0x0C000000`，B 基址 `0x1BFB2BC0`」。实测至少三套基址，且主代码段的 A 视图基址是 `0x0C0C0000`：

| 用途 | 基址 | 证据 |
| --- | --- | --- |
| 主代码段（LVGL / 应用 / 框架 UI）函数地址 | **`0x0C0C0000 + off`**（再或上 thumb 位 1） | 全镜像 1,539,774 个奇数字里，`(W & ~1) - base` 落在 `analysis/fw-functions.csv` 函数起点上的计数：`0x0C0C0000` → **18894**；`0x1BFB2BC0` → 1252（巧合量级）；`0x0C000000` → 375；`0x2C0C0000` → 37；`0x1C000000` → 29 |
| rodata / 字符串 | **`0x2C0C0000 + off`** | 控制中心字符串簇 `file 0xAD6000–0xAD7000` 里 144 个字，141 个 `W - 0x2C0C0000` 落在串起点（允许后缀合并）；换成 `0x2C100000` 只剩个位数 |
| arc 段（及部分 LVGL 段） | `0x1BFB2BC0 + off` | 16 号文档的 `0x1C064068`（arc ctor，`off 0xB14A8`）在文件里确有 1 处字面量 `0x1C064069`；换成 `0x0C0C0000 + 0xB14A8` 则 0 处 |

交叉验证（都来自 Chaos 真机跑通的常量）：

- `obj_clear_state`：Chaos 用 `0x0C58_8519`，`fw_addr 0x004C8518`；文件 `0x4C8518` 是 8 字节跳板 `5ff800f0` + 目标 `0x1C028D39`，`0x4C8518 + 0x0C0C0000 = 0x0C588518` ✓
- `obj_add_event_cb`：Chaos 用 `0x0C58_83F1`（跳板 `file 0x4C83F0` ✓），控制中心应用里有 46 处 `bl 0x4c83f0`。

**对 LVGL 样式线的意义**：`docs/地址表.csv` 里的 `0x0C0xxxxx` 形态地址若是由「`0x0C000000 + file_off`」换算来的，就系统性少了 `0xC0000`。但要注意**基址错不能解释全部**——抽查 `地址表.csv` 那两条样式地址：

- `lv_obj_set_local_style_prop = 0xc107790`：对应 `file 0x107790`，落在函数 `0x107780`（48 B）的 `+0x10` 处，是一条 16 字节的 `ldr r3,[r3,#0x1c]; cbz; blx r3; pop` 尾巴。真机 VA 应为 `0x0C1C7790`。文档记的「HardFault」与此一致（少 `0xC0000` 正好落在别的函数中段）。
- `lv_obj_set_style_bg_opa = 0xc108374`：对应 `file 0x108374`，落在函数 `0x108354`（434 B）的 `+0x20` 处，**不在指令边界上** → 这条的 `file_off` 本身就错，不能只靠基址修正救回。

⇒ 若要复活样式线：先把 CSV 全表按 `+0xC0000` 重算一遍候选 VA，再逐条用「落在函数起点 / 指令边界」筛，剩下的才是真错表项。

## 4. 控制中心是两段代码

| 区域 | 文件偏移 | 身份 | 关键引用 |
| --- | --- | --- | --- |
| 框架控制中心页 | `0x442000–0x455000` | framework 的 CC 页（Canopus 记的 `0x0c504c20` = `file 0x444C20`，同一基址体系 ✓） | `/data/app/ctrl/ctrl.db`、`orderlist_v001`、`add.bin`/`delete.bin`、`control_edit.ctl_center`、`com.xiaomi.miwear.control_center` |
| miwear 控制中心应用 | `0x55B8F0–0x564000` | 原生 C 应用，日志串 `" %s: page_main create"`（`file 0xAD6EF0`，引用点 `0x55EEEC`） | `raise_open.bin`、`raise_bright_open.ctrl`、`wristlift.settings`、`flashlight.appname`、`name.find_phone`… |

## 6. 磁贴描述结构与 `file 0x4424C0`

`file 0x4424C0`（442 B，`push {r4,r5,r7,lr}`，入口 `memset(desc, 0, 0x28)`）：

```
void tile_desc_init(struct tile_desc *d /*r0*/, int type /*r1*/);   // type 0..8，>8 直接返回
```

结构（`sizeof = 0x28`）：

| 偏移 | 内容 | 写入方式 |
| --- | --- | --- |
| `+0x00` | 8 字节「标签/名字」二元组 | `bl 0x3FED68(id, buf8)` 后 `ldrd`/`stm` 搬入；`id`：game_mode=`0x16`、disturb=`9`、alarm=`4`、raise=`5`、bright=`6` |
| `+0x08` / `+0x0C` | 图标路径 ×2（初始同值） | `strd r3, r3, [d, #8]`，`r3` 是字符串字面量 |
| `+0x10` | open 键（`0x125C38(keystr)` 的返回值） | `str r3,[d,#0x10]` |
| `+0x14` | close 键 | 同上 |
| `+0x18` | 第三键（settings / appname / sport） | 同上；二键磁贴止于此 |
| `+0x24` | **可选 handler** | 仅 disturb 写入 `0x0C502695`（=`file 0x442694`） |

九种类型的字面量（`file` 偏移 → 字符串）：

| # | 图标 | 键 1 | 键 2 | 键 3 |
| --- | --- | --- | --- | --- |
| 0 | `0x44260C` `.../game_mode.bin` | `game_mode_open.ctrl` | `game_mode_close.ctrl` | `game_mode.sport` |
| 1 | `0x44261C` `.../disturb_open.bin` | `not_disturb_open.ctrl` | `not_disturb_close.ctrl` | `disturb.settings` |
| 2 | `0x442630` `.../alarm_all.bin` | `alarm.appname` | — | — |
| 3 | `0x442638` `.../raise_open.bin` | `raise_bright_open.ctrl` | `raise_bright_close.ctrl` | `wristlift.settings` |
| 4 | `0x442648` `.../flashlight_all.bin` | `flashlight.appname` | — | — |
| 5 | `0x442650` `.../findphone_all.bin` | `name.find_phone` | — | — |
| 6 | `0x442658` `.../setting_all.bin` | `settings.appname` | — | — |
| 7 | `0x442660` `.../battery_all.bin` | `longlife.ctrl` | — | — |
| 8 | `0x442668` `.../bright_open.bin` | `always_bright_open.ctrl` | `always_bright_close.ctrl` | `display_on.sport` |

（`dnd_0.bin` @ `0x442690`、`dnd_%d.bin` @ `0x442758` 是勿扰动画图标，不在 9 类表里。）

相邻小函数：

- `file 0x44267A`（26 B）：`*(u32*)r0` 取对象、写全局 `0x2010FE0C` 的字节、`bl 0x443C78(obj, "dnd_0.bin")` —— 强制把勿扰图标复位；

## 7. 应用侧的点击回调

- `obj_add_event(obj, cb, filter, udata)` = `lv_obj_add_event_cb`，跳板 `file 0x4C83F0`（VA `0x0C5883F0`）；`filter = 7` = `LV_EVENT_CLICKED`。
- 该段内 46 处注册点：`0x551D14 0x551DE8 0x551FA8 0x5520BC 0x552398 0x5527AC 0x5532AC 0x5534D8 0x553BC0 0x5542F4 0x5585D4 0x558A58 0x559D94 0x55A2B8 0x55A2C4 0x55A810 0x55B374 0x55B380 0x55B778 0x55BA70 0x55BF44 0x5602D8 0x5604AC 0x560D04 0x562614 0x562628 0x562634 0x5627AC 0x5627C0 0x5627CC 0x562874 0x562888 0x562894 0x563BBC 0x5643E8 0x564A24 0x566694 0x566A08 0x5674D4 0x567DF8 …`
- 注册形态（`0x55B36C`）：`r3=udata, r2=7, r0=obj, r1=cb|1 → bl 0x4C83F0`；回调是同一池里的字面量，如 `0xC61ACC` → `file 0x55ACCC`。
- 完整例子 `file 0x55ACCC`（计时器磁贴，184 B）：`push{r4,r5,r7,lr}` → `bl 0x4C8210`(`lv_event_get_code`) → `cmp r0,#7`，非点击即返回；点击后 `0x31AE94(0x2CB87D88, 1)`、`0x5580E8()`（取计时器会话，全镜像仅 2 个调用者：本函数与 `0x55BDF4`）、`0x5581D4(r5)`、`0x557448()`，失败分支打 `" %s: run page create"` / `" enter state:%d"` / `"session create failed"`。

## 8. 这条线上排除过的死路（不要重走）

1. **「字符串无引用」是被错误基址骗的**：`control_center.settings`、`orderlist_v001` 等在 `0x0C000000`、`0x1BFB2BC0`、`0x2C100000` 下都 0 命中，换成 `0x2C0C0000` 立刻有 1/5 处 → 先定基址再谈「有没有引用」。
2. **地址投票要用带「后缀合并」的判据**：字符串指针允许指向长串中间（`"false"` 在 `"...true -> false"` 里），只认「前一字节为 NUL」会误杀，但认太松又会把 `0x2C100000` 抬上去。
3. **单点命中不可信**：指令字节巧合会造出大量假指针；必须做全集统计并比较多个基址的量级（18894 vs 1252）。
4. **`0x2C100000` 是错的**（本会话中途的误判）：它也能让个别 word 落在串起点，但统计峰值在 `0x2C0C0000`。
5. **`dis.js` 参数必须是带 `0x` 的十六进制串**：传十进制会被 `parseInt(x,16)` 误读 → `RangeError: offset is out of bounds`（`HEAP8.set` / `writeArrayToMemory`）。
6. **线性反汇编遇函数内字面量池会跑飞**（如 `0x55BEEC`、`0x55D704`）：看到解出的「指令」把 `0x2cxxxxxx`/`0x0cxxxxxx` 常量当操作数、且后续明显不合理时，说明已进池子，从 `b`/`bl` 目标续。
7. **`analysis/*.csv` 的 `va` 列是伪基址**（`0x1BFB2BC0 + off`），只有 `file_off` 列可信。

## 9. 若要重启这条线：最小验证清单

1. （最便宜）静态找 `0x4424C0` 的调用者：它没有 `bl`/字面量 → 从「RAM 里的函数指针表」入手，或在真机对 `0x0C4424C0` 下断点/插桩，看 `r1`（type）从哪来、`r0`（desc）存到哪。拿到这一步才有 `type → 磁贴对象` 的映射。
2. 确认二键磁贴（alarm/flashlight/findphone/settings）点击是否走 `app_launcher_*`；若走，方案 D 可用，且不需要写 flash。
3. 只读打点：在 Chaos 里 dump 磁贴对象 / `desc`（不改任何东西），确认地址对得上，再评估写的风险。

## 10. 工具备忘

- 反汇编：`node tools/dis.js <start> <end> [base]`（十六进制带 `0x`）。
- 函数表：`analysis/fw-functions.csv`（`va, file_off, size_estimate, prologue, bl_count, callers`）。
- 字符串表：`analysis/fw-strings.csv`（`va, file_off, length, text`，`va` 不可用、`file_off` 可用）。
- 查「谁指向某字符串」：按 `0x2C0C0000 + off` 在 4 字节对齐字上全镜像扫，再读后缀判合法性。
- 查「谁 `bl` 到某函数」：手写 BL 解码（`h1 & 0xF800 == 0xF000 && h2 & 0xD000 == 0xD000`，`I1=(J1^S^1)&1`、`I2=(J2^S^1)&1`）。
