# 13 · 表盘打包格式（.face / .bin）

> **这篇讲什么**：小米 Vela 手环 Lua 表盘的二进制容器格式，以及如何用 `tools/facebuild.js` 直接把一个 `main.lua` 打成可安装的表盘文件。
> **结论是什么**：格式已完全解开，打包器能**逐字节重现**官方样本 `Accelerometer.face`（99124 B，0 字节差异），因此可以脱离 Windows 工具链自行出包。
> **依赖哪几篇**：06（内核模块系统）、07（Canopus，Lua 表盘的用途）。

---

## 为什么需要自己打包

原本的三条路都堵住了：

| 方案 | 问题 |
|---|---|
| Mi-Create / 表盘自定义工具 | 图形界面，只能在 Windows 上点 |
| Mi8WfBinTool | Java 命令行，本机没有 JVM，磁盘也装不下 JDK |
| AIoT IDE | 官方 IDE，同样要装 |

于是改为逆向格式、自己出包。关键是有了一份「输入工程 + 输出成品」的完整对照样本：

- 成品：`ref/lua-wf/Accelerometer.face`（99124 B）
- 源码：`https://github.com/m0tral/MiWatchLuaWatchfaces` 的 `MiBand8Pro/Accelerometer`
- 同仓库 `MiBand10Pro/UorbGPS/` 是**本机型**（DeviceType=567）的工程，但仓库里没有编译产物

## ⚠️ 先纠正一个常见误解

表盘**不是 zip**。它是一个自定义二进制文件，魔数 `5A A5 34 12`。所以「把 `main.lua` 压缩打包」的思路是错的。

## 整体布局

```
0x000  文件头 0xA8 字节
0x0A8  face header 0x58 字节 = 11 组 (u32 count, u32 offset)
0x100  基础元素定义表        1 项 × 16 字节
0x110  脚本资源定义表        N 项 × 16 字节
...    基础元素属性（props） 32 字节
...    脚本资源块            每块 4 字节对齐
...    预览图块
```

每个区的实际位置由 face header 的 `offset` 字段给出，不写死；上面的数字是样本的取值。

## 文件头（0x00–0xA7）

| 偏移 | 类型 | 含义 | 样本值 |
|---|---|---|---|
| 0x00 | u32 | 魔数 | `5A A5 34 12` |
| 0x10 | u32 | 设备/类型标志 | `0x800` |
| 0x1C | u16 | 表盘数量 | 1 |
| 0x1E | u16 | 样式数量 | 0 |
| 0x20 | u32 | 预览图块偏移 | `0x11E50` |
| 0x28 | 9 B | 数字 ID（ASCII） | `"167210065"` |
| 0x68 | 60 B | 表盘名（ASCII，`\0` 补齐） | `"Accelerometer"` |

## face header（0xA8 起，11 组）

| 组 | 相对偏移 | 含义 |
|---|---|---|
| 0 | +0x00 | 预览（count 恒 0，offset = 预览块） |
| 1 | +0x08 | 基础元素定义表 |
| 6 | +0x30 | 脚本资源定义表 |
| 其余 | — | 样本中 count 全为 0 |

## 定义项（16 字节）

```
+0   u16  index
+3   u8   type     0 = 基础元素，5 = 脚本/资源
+8   u32  offset   指向数据
+12  u32  length   未对齐的原始长度
```

## 资源块（脚本）

```
+0    u32  低 24 位 = 内容长度，高 8 位 = 文件名长度
+4    16 B 全 0
+20  文件名 ASCII，形如 "lua/main.lua"（带 lua/ 前缀）
+..  内容原文
```

块与块之间按 **4 字节**对齐，填充 0；定义项的 `length` 记的是对齐前的长度。

注意：`cat.bin` 这种图片也是 `type=5`、名字 `lua/cat.bin` 的资源块 —— **type 5 就是「lua 目录下的一个文件」**，不限于 `.lua`。所以 `.ko` 模块可以作为兄弟资源一起塞进去。

## 根元素绑定

基础元素的 props 前 4 字节 = `{ u16 defIndex, u16 defType }`，指向「拿哪个资源当根」。样本里是 `02 00 00 05`（第 2 项 = `lua/main.lua`，type 5）。打包器默认把 `main.lua` 放在 index 0 并写 `00 00 00 05`。

## 预览图块

12 字节头 + 负载：`sign(u8) flags(u8) compress(u8) ?(u8) width(u16) height(u16) length(u32)`。样本 `230×328`，`length=25813`。当前打包器**原样复用样本的预览块**（所以缩略图是 Accelerometer 的截图），不影响运行。

## 打包器

```
node tools/facebuild.js inspect   <file.face>          # 打印全部结构
node tools/facebuild.js roundtrip                       # 自检：必须 0 字节差异
node tools/facebuild.js build <spec.json> <out.face>
```

`spec.json`：

```json
{
  "template": "../../../../../ref/lua-wf/Accelerometer.face",
  "name": "TUN Probe",
  "id": "167210065",
  "deviceFlag": 2048,
  "entryIndex": 0,
  "scripts": [
    { "name": "lua/main.lua", "path": "main.lua" },
    { "name": "lua/tunprobe.ko.bin", "path": "tunprobe.ko.bin" }
  ]
}
```

产物：`projects/canopus/watchfaces/tunprobe-installer/xiaomi-band-10-pro/tunprobe.face`（31,372 B）。

## 附：`.face` 与 `.bin` 是同一种容器

两者魔数相同（`5A A5 34 12`），只是扩展名不同，且存在**两代布局**：

| | 8 Pro 样本 `Accelerometer.face` | 10 Pro 容器（Chaos 实测） |
|---|---|---|
| 记录表位置 | 0x148 之后按自定义规则排 | 固定 0x148 |
| 槽位上限 | 4 | 255 |
| 资源路径 | 必须 `lua/` 前缀 | 任意 ASCII 路径 |
| 块间对齐 | 4 字节填充 | 无填充 |
| 预览块 tag | `0x400` | `0x410` |

Chaos 的 `projects/chaos/tools/container_shell.py` 对格式做了逐条实测（对比过多个真实容器），是 10 Pro 上更可信的依据。据此重写的打包器是 `tools/containerbuild.js`：

```
node tools/containerbuild.js inspect <file>
node tools/containerbuild.js build <spec.json> <out.bin>
```

产物 `tunprobe.bin`（31,422 B）：`recEnd=0x188`，2 条记录，预览块 `230×328`。

### Chaos 为什么用 `.bin`

它的容器里装的**不是表盘**：`chaos_sup.ko` + 安装器 Lua + 应用图标 + 字体占位文件，四个槽塞进一个容器，借表盘的安装通道投递。内容不是表盘，用 `.bin` 更贴切，也避免被当作表盘直接渲染。

> ⚠️ 注意：Chaos 采用 4 槽布局，与上表「上限 255」不冲突 —— 槽号只受一个字节限制，Chaos 只用前 4 个。

## 安全设计：为什么这个包不会把手环变砖

表盘是开机就加载的，这带来一个真实风险：**表盘里的脚本出错 → 开机即崩 → 无限重启**。所以包的设计把风险拆成三层，逐层隔离。

### 第一层：容器格式（用 A 版单独验证）

`probe-a.bin`（27,250 B）只有一个 `lua/main.lua`，内容仅四行 `lvgl.Label`：

- 不 `require` 除 `lvgl` 以外的东西
- 没有 `io`、没有 `os.execute`、没有 `SCRIPT_PATH`
- 不读任何资源文件

它唯一的用途是回答「这个容器格式 10 Pro 认不认」。装上去能看到 `PROBE A` 三个字，格式就通过了；看不到也没关系 —— 加载期没有任何会崩的代码。

### 第二层：脚本逻辑（B 版按钮门控）

`probe-b.bin`（32,559 B）带执行逻辑，但**加载期一行都不执行**：

- 页面加载时只画标题、提示文字、一个按钮
- 真正动作全部在 `button:onClicked(...)` 里
- 加了 `run_attempted` 闸门，本次开机只允许触发一次

关键性质：**按钮状态不会被保存**。即使按下后出事重启，下次开机表盘回到「待执行」，不会自动再跑一遍 —— 从结构上排除无限重启。

### 第三层：模块本身（只打日志）

`tunprobe.ko`（2,204 B）的构造器全文只有一句：

```c
FW_LOG(LOG_ERR, "TUNPROBE v1 loaded, fops=%p\n", (const void *)&g_fops);
```

它**故意不调用** `register_driver`。原因：那是一次跳转到固件绝对地址的调用，地址若有偏差就是硬 fault。本版本只验证「modlib 愿不愿意加载我们的 ELF，并且真的跑了 `init_array`」。`register_driver` 留到里程碑 2，那时已经有「加载链能通」这个前提。

### 结构自检

```
node tools/containerbuild.js verify <file.bin>...
```

校验项：魔数、`0xAC == recEnd`、记录表首条形状、尾记录位置、槽号连续、每条记录与前一块**首尾相接**、记录长度与 blob 内嵌长度自洽、预览块不越界、文件尾部无多余字节。

当前三个包全部通过：

```
OK probe-a.bin   27250 B  1 条
OK probe-b.bin   32559 B  2 条
OK tunprobe.bin  32850 B  2 条
```

### 仍然无法保证的部分

| 项 | 状态 |
|---|---|
| 10 Pro 真机接受该容器 | ❓ 无先例。Chaos 用同一格式但自述「尚未完成真机验收」 |
| 预览块 tag（`0x400` vs Chaos 的 `0x410`） | ❓ 沿用了 8 Pro 真实样本的 `0x400`，与载荷一致；tag 不符最多缩略图不显示 |
| 表盘脚本出错时固件是否回落 | ❓ 未验证。所以 A 版刻意不含任何可失败代码 |

失败模式的后果分级：格式被拒 → 装不进去，设备无感；脚本出错 → 黑屏或回落默认表盘；模块崩 → 重启一次。**没有一条会损坏固件分区** —— 依据是 `ota.sh` 里写 `/dev/ap`、`/dev/bl2` 的只有固件 OTA 流程，表盘安装走用户数据区（⚠️ 推断：未逐条核验安装器实现）。即便真出问题，本地有完整固件包 `firmware/10pro/fw.bin`，可用官方 app 重刷。

## 附：表盘「不会把设备搞坏」的验证方法

表盘是开机即加载的界面，脚本一抛错就可能白屏/卡住，所以交付前做了三层验证
（工具在 `tools/luacheck/`，依赖 `npm install fengari luaparse`，共 2.3 MB）。

### 第一层：语法 + 真跑（`tools/luacheck/run.js`）

用 **fengari**（Lua 5.3 的 JS 实现）在 Node 里真正执行表盘脚本，
把 `lvgl` / `io` / `os` / `require` / `SCRIPT_PATH` 全部换成 Lua 侧的假实现：

```bash
node tools/luacheck/run.js <main.lua> --expect-click
```

对两个探针脚本的输出：

```
语法      OK
加载期    OK  (os.execute 调用 0 次, 写文件 0 次, 有按钮 true)
点击后    OK  (执行: insmod /data/tunprobe.ko tunprobe)
```

`加载期 0 次副作用` 是硬性断言：表盘一打开就动作的写法（包括「打开即 insmod」）
在这里会直接失败，从流程上杜绝「开机即崩 → 无限重启」。

### 第二层：API 子集审计（`tools/luacheck/api-audit.js`）

用 luaparse 取出脚本用到的每个 `lvgl.*` 取值、控件类型、对象方法、控件选项，
逐个核对是否出现在「在该设备上真机跑过」的参考表盘里。参考集：

- `projects/canopus/watchfaces/canopus-installer-prod/xiaomi-band-10-pro/main.lua`（Canopus 官方安装器）
- `ref/lua-wf/band10/main.lua`（m0tral 的 Band 10 Pro 开源表盘）

结果（修改后）：

```
lvgl 取值: 10/10   控件类型: 2/2   对象方法: 6/6   控件选项: 14/14
✅ 全部是参考集里出现过的用法
```

### 这一轮据此改掉的东西

审计一开始报 `lvgl.ALIGN.TOP_MID / BOTTOM_MID / BOTTOM_LEFT` 不在参考集里。
进一步核对固件字符串表（`firmware/10pro/fwx/vela_ap.bin` 的 NUL 分隔 token）：

| token | 是否存在 |
|---|---|
| `CENTER` | ✅ |
| `OUT_TOP_MID` / `OUT_TOP_LEFT` / `OUT_BOTTOM_MID` … | ✅ |
| `TOP_MID` / `BOTTOM_MID` / `BOTTOM_LEFT` / `LEFT_MID` | ❌ 没有独立 token |

也就是说我原来写的 `ALIGN.TOP_MID` 很可能取到 `nil`，`type = nil` 会让控件位置未定义。
已全部改成 **绝对坐标 `x` / `y`**（`x`/`y` 在参考表盘 `root:Textarea { x = 5, y = 10 }` 里用过），
只保留 `ALIGN.CENTER`（两个参考表盘都用过）。

### 第三层：逻辑兜底

- 打开页面不执行任何动作，只有点按钮才跑；
- `run_attempted` 保证一次开机只执行一次，避免反复触发；
- 所有可能抛错的路径都在 `pcall` 里，出错只改屏幕文字，不影响表盘本身；
- 模块构造函数只写一行日志，**不注册任何驱动**，不碰内核对象。

### 仍然存在的风险（诚实说明）

容器格式是逆向出来的，若猜错，最可能的结果是**安装器拒绝安装**或**装上后不显示**，
而不是损坏设备。所以先装 `probe-a.bin`（纯静态、无逻辑）：它能正常显示 =
容器格式对；它不显示 = 格式有问题，此时不要装 B。

## 六、p67 真机表盘格式（2026-10 最终确认）

前面第 1–5 节描述的是手环 8 Pro 的 `.face` 与 Chaos 的文件容器，**两者都不是 p67 的
表盘格式**。用它们打出来的包 AstroBox 能读、手环会拒装（`InstallFailed`）。

真正的 p67 格式以官方 Canopus 管理器安装包为基准反推：

- 基准文件：`ref/canopus-mgr-10p-v65539.bin`（217,346 B，sha256 见 `11-参考资料.md`）
  来源 `Searchstars/Canopus-Manager-AstroBox-Release`，`manifest_v2.json` 里
  `downloads.xmb10p` 指向它，`restype` 为 `canopus`。
- 生成器：`tools/p67build.js`（`inspect` / `build` / `verify`）。
- **验收标准：`build` 能逐字节复现官方包** —— 当前已做到，
  `cmp` 无差异，217,346 B 完全一致。格式不存在猜测成分。

### 布局

| 偏移 | 内容 |
|---|---|
| `0x000` | 主头 0xA8：magic `0x1234A55A`，`0x04` 版本 `0x00010003`，`0x10` 设备标记 `0x800`，`0x14` `0x00010000`，`0x1C` u16 表盘数，`0x1E` u16 风格数，`0x20` 预览图偏移，`0x28` 12 字节 ID，`0x68` 60 字节名称 |
| `0x0A8` | 11 × (u32 count, u32 offset) 面孔指针对 |
| `0x100` | 72 字节风格名（官方为 `样式1`） |
| `0x148` | 基础定义表（pair[1]），16 B/条 |
| `0x158` | 脚本/资源定义表（pair[6]），16 B/条 |
| 表后 | 根属性记录 16 B，与定义同构：u16 index、u8 保留、u8 类型（5 = Lua） |
| 其后 | 预览图块：12 B 头（`0x10`、`0x04`、宽 u16、高 u16、长度 u32）+ 数据 |
| 其后 | 资源块首尾相接，**无对齐** |

指针对取值（单风格表盘）：

```
pair[0]  = [0x80000000, 预览图偏移]
pair[1]  = [1, 0x148]          基础定义表
pair[2..5] = [0, 脚本定义表偏移]
pair[6]  = [N, 脚本定义表偏移]
pair[7..10] = [0, 根属性偏移]
```

关键差异（对比 8 Pro `.face`）：`pair[0].count` 必须是 `0x80000000` 而不是 `0`；
版本字段是 `0x00010003`；预览图必须是 **336×480**，8 Pro 的 230×328 会被拒；
资源名要带 `_lua/<设备目录>/` 前缀。

### 资源块

20 字节头：`u32 = dataLen | (nameLen << 24)`，随后 16 个零字节，然后 ASCII 名，
然后数据。定义里的 `length` 是整块长度 `20 + nameLen + dataLen`。

官方包的四个块（可直接对照）：

```
_lua/xiaomi-band-10-pro/main.lua                                            14,174 B
_lua/xiaomi-band-10-pro/canopus_supervisor-xiaomi-band-10-pro-3.101.036.bin 71,880 B
_lua/xiaomi-band-10-pro/canopus_supervisor-xiaomi-band-10-pro-3.101.043.bin 71,864 B
_lua/xiaomi-band-10-pro/manager_icon.bin                                    54,768 B
```

### 脚本怎么取包内文件

官方 `main.lua` 用 `SCRIPT_PATH .. "manager_icon.bin"` 读同目录资源，`os.execute`
执行 shell。所以自带的 `.ko` 只要按 `_lua/<设备目录>/tunprobe.ko` 放进资源块，
脚本里 `SCRIPT_PATH .. "tunprobe.ko"` 就能读到。

### 已废弃

第 1–5 节的 `tools/facebuild.js`（8 Pro `.face`）与 `tools/containerbuild.js`
（Chaos 文件容器）仅作格式研究存档，**不要再用它们产出的包去装 p67**。
