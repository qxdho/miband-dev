# 小米手环 10 Pro 研究文档

## 这套文档要解决什么

**目标**：在小米手环 10 Pro（`p67cn` / `M2551B1` / 固件 `3.101.043`）上，用官方「小米运动健康」App 的通道打通 `fetch` 网络能力，替代第三方网桥（interconnect）。

**当前结论**：通道在两端都有代码，但手环侧缺 `/dev/tun` 设备节点，`net_tun_open` 以 `ENOENT` 失败。补上它需要内核模块，而 10 Pro 恰好是小米手环里少数带 `modlib` 模块加载能力的机型——这是目前唯一有希望的路线。

## 结论速查

| 问题 | 结论 | 状态 |
|---|---|---|
| `fetch` 模块在 10 Pro 上存在吗 | 存在，`canUse('@system.fetch')=true` | ✅ 已证实（真机） |
| 权限层会拦截 `fetch` 吗 | 不会，请求已进入 DNS 解析阶段 | ✅ 已证实（真机） |
| 应用写 `'fetch'` 而不是 `'@system.fetch'` 会怎样 | `canIUse` 返回 `false`，被当成无效模块 | ✅ 已证实（真机 + 固件） |
| 为什么连域名失败 | 手环无 DNS 解析能力 + 无网络出口 | ✅ 已证实 |
| 为什么连裸 IP 也失败（`code:7`） | 无路由，`connect()` 立即返回 | ✅ 已证实（真机） |
| `system.network.getType()` 返回 `none` 说明没网吗 | **不能这样判断**，它只报物理接口 | ✅ 已证实 |
| 官方 App 会给手环提供网络吗 | 手机侧代理已成功启动（`support net proxy = true`） | ✅ 已证实（手机日志） |
| 手环侧为什么还用不上 | `/dev/tun` 不存在，`net_tun_open: errno 2` | ✅ 已证实（手环日志，26 次无例外） |
| 10 Pro 支持内核模块加载吗 | 支持，`modlib` / `insmod` / `rmmod` / `lsmod` 齐全 | ✅ 已证实 |
| 9 Pro 支持模块加载吗 | 不支持，无 `modlib` | ✅ 已证实 |
| 能把 9 Pro 的 tun 驱动拷过来吗 | 不能，它是静态链进 `vela_ap.bin` 的，不是独立模块 | ✅ 已证实 |
| Canopus 支持 `3.101.043` 吗 | 支持，target pack 的 `firmware_sha256` 与本机镜像精确匹配 | ✅ 已证实 |
| Chaos 支持同版本吗 | 支持，但硬编码绝对地址 | ⚠️ 推断 |
| 装上 tun 驱动就能通吗 | 还要手机侧持续下发 `remote_net_state_switch` | ❓ 待定 |

## 术语表

| 术语 | 含义 |
|---|---|
| **快应用 / quickapp** | 手环上的应用形态，`/data/apps.json` 里登记，跑在 QuickJS 里 |
| **JIDL** | 快应用 JS API 的接口描述层，决定哪些模块被注册 |
| **feature 裁剪** | 编译期按 `Kconfig` / Makefile 决定把哪些子系统打进 `vela_ap.bin` |
| **Miwear NET** | 小米私有协议：把手机的网络通过 BLE 以 TUN 设备形式延伸到手表 |
| **interconnect** | 小米的跨设备互联框架；用户想绕开的那条第三方网桥路线 |
| **modlib** | NuttX 的可加载模块子系统，对应 `.ko`，通过 `insmod` 载入 |
| **Canopus** | 第三方模块加载器 + 应用运行时，Lua 表盘驱动 |
| **Chaos** | 另一个第三方模块框架，Rust 编写，自带渲染引擎 |
| **vela_ap** | 手环的应用处理器镜像，即整个 NuttX + 快应用运行时 |
| **TUN** | 虚拟网络设备，内核把 IP 包交给用户态程序，再由它转发出去 |

## 状态标记约定

| 标记 | 含义 |
|---|---|
| ✅ 已证实 | 有直接证据（真机日志、固件字节、精确匹配的哈希） |
| ⚠️ 推断 | 证据支持但未闭环，或只在单一来源上成立 |
| ❓ 待定 | 尚无证据，或证据互相矛盾 |
| ❌ 已推翻 | 曾被写入文档，后被新证据否定（只保留在附录） |

## 证据分级

1. **真机实测**：手环 / 手机日志里的一手输出
2. **固件字节**：从 `vela_ap.bin` 里直接读出的字符串、指针、指令
3. **上游源码**：NuttX、LVGL、开源项目的公开代码
4. **社区说法**：论坛、GitHub issue，需按机型单独标注

正文中每条结论都标了等级；第 4 级不作为单独依据。
