# 14 · 应用隐藏/显示：为什么必须重启，以及两种取舍

> **这篇讲什么**：Chaos 应用管理里“隐藏/显示”为什么要重启才生效、固件到底按哪份状态建桌面图标，以及 2026-10-20 之后提供的两种模式。
> **结论是什么**：固件没有可用的“运行时重新注册本地快应用”入口；想免重启，只能保留 `/data/apps.json` 条目，用注册表隐藏位 + 开机补偿维持隐藏状态。两种模式各有代价，默认仍是重启模式。

---

## 1. 现象

- 隐藏应用后，桌面图标立刻消失（`app_launcher_del` 成功）。
- 重启后想让应用回来，Chaos 写回 `/data/apps.json`、点“显示”，图标不出现；必须再重启一次。
- 日志里能看到开机时一批 `[launcher] app_launcher_del: app_launcher_del app`，没有 `add icon`。

## 2. 固件实际维护三层状态

| 层 | 位置 | 作用 |
|---|---|---|
| 持久化名单 | `/data/apps.json`、`/data/apps.json_hide` | 开机时决定“哪些应用已安装” |
| 内存注册表 | `APP_REGISTRY`（0x200E_B640）链表 | 运行时按包名/app_id 找应用；节点 +0x08 包名、+0x0C 图标路径、+0x10 app_id |
| 桌面图标 | `LAUNCHER_DESKTOP_LIST` + LVGL 对象 | 用户看到的图标；`app_launcher_del/add` 只改这一层 |

隐藏的常规做法是把条目从 `apps.json` 搬到 `apps.json_hide`。**条目一旦不在 `apps.json`，下次开机固件就认为它没安装，不会为它建注册表节点。**

## 3. 为什么“清隐藏位”没用

`app_launcher_add`（0x0C51_3A44）先按 app_id 查注册表节点；节点不存在直接返回 0。节点存在时才进入建记录回调 `FUN_0C513700`：

```text
ldrb.w r2, [r0, #0x3c]
lsls   r1, r2, #31        ; bit0 = “应隐藏”
bmi    0x0C5137A4         ; 打 “The app need hidden”，返回 0
```

也就是说：

- 对“还在注册表里的节点”，清 `+0x3C` bit0 后 `add` 能成功——这是有用的；
- 对“重启后根本没注册”的应用，`find_node` 返回 0，清位代码执行不到，`add` 也不可能成功。

后者才是用户遇到的“必须再重启”的根因。

## 4. 有没有运行时重新注册的入口

查过固件与公开实现，结论是**没有可安全调用的通用入口**：

| 入口 | 结论 |
|---|---|
| `quickapp_register_app`（0x0C54_9679） | 能建节点并调 `app_launcher_add`，但传入空 `extra` 会在 `strdup(NULL)` 崩溃（已真机触发 busfault）；它是 interconnect 内部路径，不保证本地快应用可启动 |
| `quickapp_install_locally` | native handler 最终仍走 `quickapp_register_app`，参数来自 proxyquickapp 内部，Lua/模块无法直接构造 |
| `launcher_data_init` | 只在开机总初始化跑一次，没有对外 reload API |
| 社区实现 | [Shellpp-II 的应用管理文档](https://github.com/Shellplusplus/Shellpp-II-App/blob/main/docs/application-management.md) 同样明确“hide/show 提示重启后生效”，没有免重启注册 |

因此所谓“两全其美”的运行时补注册，在现有固件上没有可靠实现。

## 5. 两种模式（Chaos 的开关）

页 1 顶部新增开关 **“免重启显示”**，状态存在 `/data/chaos/appmgr_apply.cfg`：

### 模式 A：重启生效（默认，开关关）

- 隐藏：条目 `apps.json` → `apps.json_hide`，同时置节点 `+0x3C` bit0、删图标。
- 显示：写回 `apps.json`，重启后固件重新注册；本机若还能找到节点则立即 `add`。
- 与其它工具读写同一份配置的语义一致，最安全。

### 模式 B：免重启显示（开关开，保留条目）

- 隐藏：**不动 `apps.json`**，只把包名记进 `/data/chaos/appmgr_keep.bin`，并置 bit0、删图标。
- 显示：从名单里摘掉，清 bit0、`add` 图标，**立即生效**。
- 开机补偿：模块维护定时器在启动窗口结束后读名单，逐个置 bit0、删图标，避免图标在桌面上留下来。
- 代价：
  - 开机瞬间图标可能闪现（取决于 `rc.d` 与桌面初始化的先后）；
  - 其它工具读 `apps.json` 会认为该应用仍“可见/已安装”；
  - 切换模式前已经在 `apps.json_hide` 里的应用，第一次显示仍要重启一次（节点要等下次开机才注册）；
  - 从模式 B 切回模式 A 时，Chaos 会把名单里的条目搬进 `apps.json_hide`，随后仍需重启。

两种模式都只改应用名单/图标，不删除应用数据。

## 6. 排除项（与模式独立）

`/data/chaos/appmgr_excl.bin`（`EX01` + 40×44 字节包名）记录“不参与一键隐藏/显示”的应用；页 1 不显示被排除项，页 7 可逐项取消。排除项只影响一键操作，不影响单点隐藏/显示。

## 7. 验证清单

1. 模式 A：隐藏 → 重启 → 可见列表为隐藏态 → 点显示 → 提示“重启后显示” → 重启后图标回来。
2. 模式 B：隐藏 → 图标立即消失 → 点显示 → 图标立即回来（不重启）。
3. 模式 B：隐藏 → 重启 → 图标不回来（允许开机瞬间闪现）。
4. 模式 B 切回 A：已有隐藏项进入 `apps.json_hide` → 重启后仍隐藏。
5. 排除项：加入后一键隐藏/显示跳过它；页 1 列表不显示；页 7 可取消。

## 8. 未决

- 开机补偿的实际时间窗与图标闪现时长，需要真机录像确认。
- 模式 B 下其它工具（米环管理、SmartHome）读到“可见”后的行为，未做交叉验证。
- 若未来固件暴露可靠的本地安装/重注册 API，可去掉模式开关，统一为免重启。
